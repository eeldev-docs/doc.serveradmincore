Player Component

ServerAdminCore Player Component (UServerAdminCorePlayerComponent) is the bridge between a player and Server Admin Core. The server adds it to every player controller automatically (Auto Add Player Component). You can also add it to your player controller Blueprint yourself, or use your own subclass with Player Component Class.

Get it with Get Server Admin Core Player Component (Player Controller), or on the client with Get Server Admin Core → Get Local Player Component.

Chat​

FunctionDescription
Send Chat Message (Message)Sends chat. Messages with the command prefix run as commands. Muted players are blocked.
Is MutedReplicated mute state
EventDescription
On Chat Received (Sender Name, Sender Id, Sender Group, Message)A chat message from any player
On Server Message (Message)A private message from the server ("You are muted", welcome message, /msg)
On Announcement Received (Message, Type)An announcement

Building a chat box​

  1. In your chat widget's On Text Committed: Get Owning Player → Get Server Admin Core Player Component → Send Chat Message.
  2. In Construct: bind On Chat Received, On Server Message, On Announcement Received and On Command Output, and add a line to your chat log in each.
  3. Use Sender Group with Get Group on the server, or your own lookup, to color names or add a [ADMIN] tag.

Commands​

Function / EventDescription
Execute Command (Command Line)Runs a command. The prefix is optional.
On Command Output (Lines, Result)The output of the command

Permissions on the client​

The component replicates the player's group and permissions to the owning client only:

FunctionDescription
Has Permission (Permission)Wildcard aware check
Get Group Name, Get Group Priority, Get Permissions
On Permissions ChangedFires when the group, permissions or mute state change

Use these to show an admin button only to staff. The server always checks permissions again, so a modified client can't do anything it isn't allowed to.

Kick reason​

EventDescription
On Kicked (Reason)The local player is being kicked. Fires just before the disconnect.

The reason is also stored on the subsystem, so you can show it after the client is back on the menu map. See Showing the kick reason to the player.
